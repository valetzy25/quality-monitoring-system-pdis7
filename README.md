# Quality Monitoring System

Прототип контроля качества учебного модуля по объективным событиям LMS и учебных сервисов. Python 3.10+; внешние библиотеки не требуются. Выбран вариант сдачи **В (CLI)**. Данные в `examples/learning_events.csv` учебные, а не сведения реальных студентов.

Репозиторий проекта: https://github.com/valetzy25/quality-monitoring-system-pdis7

## Архитектура

Сервисы LMS, автотестов, Git, ревью и поддержки передают события в `learning_events` (DDL: `migrations/001_learning_events.sql`). Экспорт CSV подаётся в `src/quality_monitor.py`. Пайплайн валидирует UTC-время и поля, устраняет повторные `event_id`, считает метрики по студенту, группе и модулю, применяет пороги из `config/quality_gates.json`, выводит GREEN/YELLOW/RED и причины RED. Внешних уведомлений прототип не отправляет: в JSON возвращается код рекомендуемого действия.

Семь событий: `assignment_published` (открывает задание и формирует состав группы), `submission_created` (передана работа), `autotest_completed` (результат попытки), `activity_recorded` (commit или просмотр), `homework_reviewed` (завершена проверка), `support_ticket_opened` (создан вопрос), `support_ticket_answered` (дан ответ). `entity_id` связывает сдачу с ревью и вопрос с ответом. Источник события задаёт уникальный `event_id` и UTC-время; при конфликте двух строк с одним идентификатором импорт останавливается.

## Пороги и наблюдение

Окно для проверок ДЗ, первых попыток и поддержки — 30 суток. Время считается в часах по UTC. Для активности используется последний commit/просмотр за всё время; при их отсутствии отсчёт идёт от открытия задания. Группа получает худший статус из четырёх ворот, модуль — худший статус его групп. Недостаток данных обозначается YELLOW, поэтому отсутствие измерений не выглядит как успех.

| Показатель | GREEN | YELLOW | RED |
|---|---|---|---|
| Среднее время проверки ДЗ | `<24` ч | `24–48` ч | `>48` ч |
| Успешные первые попытки | `>70%` | `40–70%` | `<40%` |
| Максимальная пауза активности студента | `≤24` ч | `>24` и `<72` ч | `≥72` ч |
| Среднее время ответа | `<2` ч | `2–6` ч | `>6` ч |

Незакрытое обращение старше 6 ч переводит поддержку в RED даже без завершённых ответов. Для среднего учитываются только пары открытия и ответа. Повторная попытка теста не изменяет долю первых попыток.

## Запуск

Из корня проекта:

```bash
python3 -m src.quality_monitor \
  --events examples/learning_events.csv \
  --config config/quality_gates.json \
  --now 2026-09-26T04:00:00Z \
  --group group-25 --module module-7 \
  --json-out examples/result.json
```

Для машинного вывода добавьте `--json`. Без `--now` используется текущее время UTC. JSON содержит `groups`, агрегированные `modules`, `students`, четыре метрики с выборками, причины RED и `input_stats` по дубликатам/будущим событиям. Проверка:

```bash
python3 -m unittest discover -s tests -v
```

Пример входа находится в `examples/learning_events.csv`; рассчитанный ответ — в `examples/result.json`. Для самостоятельного запуска можно заменить CSV своим экспортом с теми же колонками. Не используйте ФИО как `student_id`: подходит обезличенный технический ID.
